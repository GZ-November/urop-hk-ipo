# 深蓝字段（不在招股书里的 33 列）采集方案

对应工作簿 `HKIPO-MB2026Q1.xlsx` 的天蓝块 `CJ:DP`。老师逻辑：这些数招股书里没有，得另外找。

## 0. 一句话结论

**33 个字段里，31 个能自动化拿到**（HKEX 官方 + 腾讯行情），
**只有 2 个（1 个月 HIBOR、银行体系总结余）当前网络不通**——
而这两个是**按日期**的市场序列，Q1 只需约 90 行的小表，一次拿到就能覆盖全部 38 家。

## 1. 可达性实测（2026-09-10）

| 来源 | 状态 | 实测证据 |
|---|---|---|
| **HKEXnews 公告检索** | ✅ 稳定 | 多次调用均 200；配发结果公告 **38/38 已定位** |

## 2. 字段 → 来源映射

### A. HKEX 配发结果公告（自动，官方，最权威）——17 列

公告标题：`ANNOUNCEMENT OF (FINAL) OFFER PRICE AND ALLOTMENT RESULTS`（38/38 已定位，索引见 `out/allotment_index.json`）

**为什么这批最好做**（实测）：

| | 招股书 | 配发公告 |
|---|---|---|
| 页数 | 600+ 页 | **14–50 页** |
| 字符 / token | ~40 万 / ~10 万 | **2.5–10 万 / 6k–26k** |
| 是否需要切片 | 必须 | **不需要，整篇一次给代理** |
| 是否需要全文检索工具 | 必须 | 不需要 |

即：**同一套流水线模式，去掉切片与检索两步**。实测 4 份：6082(47页/24k token)、
0100(50页/26k)、2692(23页/12k)、2726(14页/6k)。

**字段确实在正文里**（以 6082 公告为例实测捞到）：
`over-subscribed by more than 100 times`、**`Subscription level 2,347.53 times`**、
`valid applications 471,116`、`Final Offer Price : HK$19.60`、
独立的 **`FREE FLOAT`** 段、独立的 **`Cornerstone Investors`** 逐行表。

> 例外：**CR 配发公告日**不必读正文——直接取港交所元数据的 `DATE_TIME`，是确定性的。

**可做的交叉校验**（比招股书容易）：
1. 基石表逐行股数之和 == 表内 `Total` 行
2. 最终公开发售 + 最终配售 == 最终全球发售
3. 最终全球发售 ≥ 初始发售（规模调整权行使时）
4. 最终股数 × 最终发售价 ≈ 募资总额
5. 回拨方向与初始配比是否自洽
6. `CK` 基石占比 == 基石表股数 ÷ base offer
7. 关键数字用**正则独立提一遍**，与 AI 结果对撞，不一致则人工复核

| 列 | 字段 | 公告里怎么取 |
|---|---|---|
| CQ | Pricing date | 最终发售价段 |
| CR | Allotment announcement date | 港交所元数据 `DATE_TIME`（确定性） |
| CS–CU | Final global / public / placing shares | `Structure of the Global Offering` 表 |
| CV | Over-allotment shares actually issued | 绿鞋行使段 |
| CW | Actual clawback / reallocation description | 回拨段原文 |
| CK | Final cornerstone allocation (% of base offer) | Cornerstone Investors 表逐行股数 ÷ base offer（**表内已有"假设绿鞋未行使"百分比列**） |
| CY | Public shareholding at listing (%) | 公告的公众持股段 |
| CZ | Share base used for both ratios | 公告的持股结构段 |
| DA | Unrestricted public shareholding at listing (%) | 同上，扣除禁售 |
| DB/DC | Free float denominator (描述/股数) | 同上 |
| CJ | Cornerstone investor names | 用公告校准招股书名单 |

同时抓 `FULL EXERCISE OF THE OVER-ALLOTMENT OPTION` 公告确认绿鞋是否行使。

### B. 腾讯行情接口（自动）——约 7 列 + 1 张日期表

| 列 | 字段 | 取法 |
|---|---|---|
| DI–DL | 首日 开/高/低/收 | 该股上市首日 K 线 |
| DM | 首日成交量（股） | 同上 |
| DN | 首日成交额（HK$） | 同上 |
| DD | HSI 20 个交易日回报 | 用恒指日线：t = 招股书日前最后一个交易日，P(t)/P(t−20)−1 |

**技巧**：恒指日线自带的日期序列**就是港股交易日历**，不用另找日历——"招股书日前最后一个交易日"直接从指数序列里取。

### C. HKEX 新上市页（自动，已能用）——1 列

| 列 | 字段 | 取法 |
|---|---|---|
| DE | 近 90 日港股普通股 IPO 数 | 用新上市列表，窗口 [D−90, D)，剔除转板/介绍上市/再融资 |

### D. 招股书（我们现有流水线已能取）——5 列

| 列 | 字段 | 说明 |
|---|---|---|
| CL | 基石最早解禁日 | 基石协议禁售条款 + 上市日 |
| CX | 净募资额 | Use of Proceeds 的估计净额；最终以配发公告为准 |
| CM | 认购倍数 | **优先用配发公告原文**（公告给申请股数/倍数），aipo 不通故不再依赖 |
| CN/CO | 申购人数 / 有效申请股数 | 配发公告的申请结果段 |
| DP | 公司中文名 | 招股书封面（已能取） |

### E. 规则归类（一次性建表，不逐家抓）——2 列

| 列 | 字段 | 取法 |
|---|---|---|
| DN | Offer mechanism | 按招股书刊发日落在哪个制度版本 + 招股书披露的回拨安排判定 |
| DO | Applicable IPO rules / transition basis | 同上（如 FINI 自 2023-11-22、新定价机制自 2025-08-04） |

这两列建立一张**生效日期对照表**即可，属于确定性判断，不需要联网。

### F. HKMA 开放 API——2 列（✅ 已跑通并填入）

| 列 | 字段 | 状态 |
|---|---|---|
| DF | 1-month HIBOR before prospectus (%) | **已填 38/38** |
| DG | Banking system aggregate balance (HK$) | **已填 38/38** |

**关键：这两列不是"每家一个值"，而是"每个交易日一个值"。**
Q1 2026 只涉及约 120 个交易日：

> 一张 `日期 → HIBOR 1M / 总结余` 的表（120 行），**一次拿到覆盖全部 38 家**。

**已实现**：`tools_fetch_hkma.py`（取数）→ `data/manual/hibor_balance.csv`（120 行）
→ `tools_import_market_csv.py`（按招股书日期 join 写入 DF/DG）。

两个实测坑：
1. **该 API 忽略 `from`/`to`**，只按"最新在前"返回；要靠大 `pagesize`（1000 覆盖约 4 年）
   或 `offset` 回溯，再本地按日期过滤。
2. **偶发 502**（Kong 网关间歇性抽风）；根路径返回 `no Route matched` 即说明网关可达，重试即可。


**我们这边提供 CSV 导入接口**：把表放成 `data/manual/hibor_balance.csv`（列：`date,hibor_1m,aggregate_balance`），流水线按日期 join 即可，值本身不需要 LLM。

## 4. 工程要求（针对网络不稳定）

1. **重试 + 指数退避**：每个请求 3 次、间隔递增；失败记录到 `out/fetch_errors.json`。
2. **落盘缓存**：原始响应按 `来源/字段/日期` 存到 `data/raw/`，重跑不重复请求。
3. **来源留痕**：每个值记录 `source_url + retrieved_at + 原始字段名`，写进抽取 JSON 的 `quote/notes`。
4. **只用官方源做结论**：第三方（腾讯）只用于市场行情，且与东财互为备份。
5. **不硬依赖单一站**：任一源失败时，该字段填 `NaN` 并标注原因，不阻塞其它字段。
