## 2. 浅蓝 L:CI —— 招股书 ⏳

**来源**：港交所披露易（HKEXnews）的招股书 PDF，共 38 份，约 370MB
下载后在本地按 `HKIPO-MB<股票代码>.pdf` 命名。

**采集方法**：`prospectus_pipeline` 六阶段流水线

| 阶段 | 命令 | 做什么 |
|---|---|---|
| 1 定位 | `run.py find` | 两段式查港交所：`prefix.do` 取股票内部 ID → `titleSearchServlet.do` 按 ID 拉文档，挑 `Listing Documents – [Offer for Subscription]`。**38/38 已定位** |
| 2 下载 | `run.py download` | 5 并发下载 PDF |
| 3 打包 | `run.py prepare` | PDF → 页级文本 → 按章节锚点切片 → 生成抽取包（含字段清单 + 手册规则 + 种子切片） |
| 4 抽取 | `workflows/prospectus_extract.js` | 每个包一个代理：**packet 只是起点，缺失处用 `tools_search.py` 在全文里自己检索**；输出严格 JSON（值 + 页码 + 原文引用 + 置信度） |
| 5 校验 | `run.py validate` | 契约完整性 / 证据核验（引用页必须真实存在）/ 股份与财务勾稽；输出 `gate_pass` |
| 6 写回 | `run.py write` | **只有闸门通过才写**；按规范化表头解析列；只赋值不改样式；默认按手册写 `NaN`/`NA` |

**76 列里真正参与 AI 抽取的是 42 列**（`schema/fields.json`，即表中标 ★ 的字段）：

- 浅蓝 L:AY 共 40 列：股份结构 L:S、价格 T:U、三年财务 V:AN、承销 AO:AQ、业务 AR:AS、附加财务 AT:AY
- 深蓝 CJ（基石名单）、DP（中文名）各 1 列 —— 老师虽然给它们深蓝，但**实际来源是招股书**

**其余 36 列浅蓝**（AZ:CI）也来自招股书，属于扩展维度（前十大：注释/VC‑PE/实控人/行业代码/公司背景/报表口径/发行流程/财务质量），**尚未纳入抽取 schema**，需要时按同一套模式扩列即可。

**状态**：流水线在 Biren（6082.HK）上端到端验证通过 —— **42/42 字段、0 缺失、契约与勾稽全过、独立复核判 pass**。38 家尚未批量跑。

### 3.1 HKEX 配发结果公告 —— 18 列 ✅ **已完成**

公告标题：`ANNOUNCEMENT OF (FINAL) OFFER PRICE AND ALLOTMENT RESULTS`
**38/38 已定位**，索引见 `out/allotment_index.json`（含公告时间与 PDF 链接）。

| 列 | 字段 | 公告里怎么取 |
|---|---|---|
| CK | Final cornerstone allocation (% of base offer) | 基石表逐行股数 ÷ base offer；表内已有"假设绿鞋未行使"的百分比列 |
| CM | Subscription Ratio (times) | 申购结果段（**不再依赖 aipo**，该站连不上） |
| CN / CO | Public applicants / valid applied shares | 申请结果段 |
| CP | Public subscription original wording | 同上原文 |
| CQ / CR | Pricing date / Allotment announcement date | CQ 公告通常不给，全写 NA；CR 取港交所元数据 DATE_TIME |
| CS–CU | Final global / public / placing shares | `Structure of the Global Offering` 表（未行使绿鞋口径） |
| CV | Over-allotment shares actually issued | **不从配发公告推断**。上市后 45 天内检索港交所：有行使公告则填实际配发股数，无则填 0 |
| CX | Net IPO proceeds to issuer (HK$) | 公告净募资（最终值，覆盖招股书估计值） |
| CW | Actual clawback / reallocation description | 回拨段原文 |
| CY | Public shareholding at listing (%) | 公众持股段 |
| CZ | Share base used for both ratios | 持股结构段 |
| DA | Unrestricted public shareholding at listing (%) | 同上扣除禁售 |
| DB / DC | Free float denominator（描述 / 股数） | 同上 |

**采集方法**：`run.py allot` 下载+打包 → `workflows/allot_extract.js` 分批抽取 → `run.py greenshoe` / `cornerstone` 确定性回填 CV/CK → `validate --target allot` 闸门 → `write --target allot`。

**确定性回填（不让模型猜）**：
- `col_CV`：港交所检索《行使超额配售权》公告。38 家中 **18 家实际行使**（部分/全部），20 家窗口已过未行使填 0。
- `col_CK`：招股书 0 处「基石投资者」且公告无基石章节 → 填 0。确认无基石 4 家：`2526 / 2649 / 2729 / 3625`。
- `col_DA/DC`：公告未直接给 free float 时，`DA = (CS − CK×CS) / CZ`，`DC = CZ`。

### 3.2 HKMA 开放 API —— 2 列 ✅ **已完成**

### 3.3 腾讯行情接口 —— 7 列 ✅ **已完成**

| 列 | 字段 | 取法 |
|---|---|---|
| DD | HSI return over 20 trading days before prospectus (%) | 恒指日线 `hkHSI`：t = 招股书日前最后一个交易日，P(t)/P(t−20)−1 |
| DH–DL | 首日 收 / 开 / 高 / 低 / 成交量 | 个股日线 `hk<code>` 的上市首日 |

### 试点暴露的两个真问题（已被加固后的闸门拦住）

1. **`col_CV` 引文编造**：模型把"超额配售 42,726,800 股"与"其后悉数行使"拼成一句，
   但"后一句"不在本公告里（来自 2026-01-28 的行使公告）。数值恰好正确，**证据链不成立**。
2. **`col_CO` 漏采**：有效申请股数其实可由公告第 29–31 页
   `BASIS OF ALLOCATION UNDER THE HONG KONG PUBLIC OFFERING` 表逐档加总得到
   （Pool A 5,404,167,400 + Pool B 23,669,492,400 = **29,073,659,800**），
   模型因正文未直接给总数而填了 NaN。

### 已做的加固

- **引文覆盖率闸门**：`contracts.py` 新增 `_verbatim_coverage`，
  要求引文 ≥ **90%** 的词能在**所指那一页**找到连续原文；低于门槛直接判 ERROR。
  实测把 4 处问题引文（CV 0.67 / DA 0.61 / CK 0.82 / CU 0.86）全部拦下，
  `gate_pass=False`，**未写入工作簿**。
- **性能修复**：read-only 工作表的 `ws.cell()` 每次约 27ms，逐格访问导致 validate 卡死；
  改为 `iter_rows` 一次读入，**校验从 >300s 降到 1s**。

### 全量跑之前的两个小改进（建议）

1. 给 `col_CO` 的 hint 补一句：**"总数未直接给出时，去 `BASIS OF ALLOCATION` 表逐档加总"**。
2. 给 `col_CR` 的 hint 补一句：**quote 应引包首的港交所元数据，不要引正文签署日**。
