This document provides a comprehensive, bilingual reference manual for the Hong Kong IPO data collection, extraction, independent review, econometric enrichment, and empirical research pipeline. It covers both modern (2020–2026) and historical (2000–2019) listing periods, 0-token native geometric table parsing, and LLM token / API cost optimization discipline.

### Detailed Stage Breakdown / 六步工作流详述

#### Stage 1: Plan & Scope / 第一步：规划划分与工单生成
- **Command / 命令**: `python3 run.py plan <period>` (e.g. `python3 run.py plan 2025Q4` or `python3 run.py plan 2000..2026`).
- **Function / 功能**:
  - Automatically splits multi-year or arbitrary time ranges into standard `[Board x Calendar Quarter]` execution jobs.
  - Checks if cohorts already exist in `pipeline/cohorts/` (`stored` state) or need fresh collection (`new` state).
  - Outputs reproducible `run.py start` commands with exact start and end dates.

#### Stage 2: Official Discovery, Download & 0-Token Native Pre-Parsing / 第二步：官方发现、披露下载与表格预解析
- **Command / 命令**: `python3 run.py start --board <MB|GEM> --period-start YYYY-MM-DD --period-end YYYY-MM-DD`.
- **Function / 功能**:
  - Connects to HKEX official listing portals to obtain New Listing Reports. Supports both `.xls` format (via `xlrd` for listings before 2020) and `.xlsx` format (for 2020+).
  - Filters out introduction listings, transfers from GEM to Main Board, and SPACs, isolating ordinary IPOs.
  - Downloads official Prospectus and Allotment Results PDFs.
  - Invokes `src/table_parser.py` to extract high-density tabular disclosures directly using PDF geometric coordinate clustering without spending any LLM tokens. Tables are embedded inside `<!-- TABLE_START --> ... <!-- TABLE_END -->` markers.
  - Compiles the unified extraction packet (`HKIPO-MBxxxx.md`) with `--no-topics` enabled by default to prevent redundant text duplicates.
  - Generates machine-readable `work_orders.json` and exits with **Exit Code 3 (`WORK_PENDING`)**, signaling that human/agent extraction and review gates are pending.

#### Stage 3: Exit Code 3 Protocol & Lease-Scheduled Extraction / 第三步：Exit 3 协议与租约抽取
- **Exit Code 3 Protocol / 退出码 3 治理原则**:
  - Exit Code 3 is **an intentional governance boundary**, not a crash. Unreviewed raw extractions must never be silently injected into the research database.
- **Orchestrator + Subagent Model / 父智能体编排与子智能体并发**:
  - The parent orchestrator runs `python3 run.py work next --config CONFIG`.
  - Claims an **issuer-level bundled lease**: one extractor subagent processes all targets (`prospectus`, `allot`, and `gem` for GEM issuers) of an issuer in a single session. This eliminates duplicate reading of company background and share structure.
- **Fixed Financial-Period Rule (Teacher's Manual §2.3) / 固定会计期间准则**:
  - **`year-1`**: The latest period of the audited Track Record in the Accountants' Report (full year or 3–11 month stub). `col_AT` records its exact end date.
  - **`year-2` / `year-3`**: The two complete preceding financial years. Never derived by subtraction.
  - Unaudited post-track-record disclosures (e.g. quarterly figures in appendices or "Recent Developments") are **never** `year-1`.
  - Only Net Sales (`col_AH`), Profit Before Tax (`col_AK`), and Profit for the Period (`col_AN`) are annualised (`value * 12 / months`). All other fields use original values.
- **Completion / 完成**: Extractor calls `python3 run.py work finish-extract --lease <LEASE_ID>`.

#### Stage 4: Independent Dual-Blind Review / 第四步：独立双盲复核
- **Review Lease / 申领复核工单**: `python3 run.py work next --config CONFIG` yields a review lease.
- **Excerpt-First Verification / 摘要优先核查**:
  - The reviewer subagent reads the generated brief's `Review sheet`. Each populated field is presented alongside a 700-character excerpt of the original disclosure page.
  - The reviewer only needs to open full pages or execute searches if an excerpt is truncated, a validation warning exists, or a field is marked missing (`NaN`/`NA`).
- **Sign-off / 签署归档**: The reviewer generates a markdown review report containing the exact payload SHA-256 hash and completes the lease:
  `python3 run.py work finish-review --lease <LEASE_ID> --verdict pass --reviewer "ReviewerAgent"`.

#### Stage 5: Hash-Gated Write-Back & External Enrichment / 第五步：哈希回写与外部计量增广
- **Command / 命令**: `python3 run.py resume --run-dir deliverables/run_<board>_<period>`.
- **Integrity Gate / 完整性门禁**: The resume runner checks that all targets have passing review credentials matching the exact payload hash.
- **Snapshot Backup / 备份快照**: Creates a timestamped `.bak` copy of the workbook before writing.
- **Deterministic External Pipeline / 确定性外部计算流水线**:
  1. `disclosure_notes`: Computes annualisation factor `col_BC = months / 12` and writes unadjusted originals into `col_CN/CO/CP`.
  2. `market`: Fetches split-adjusted daily K-lines from Tencent Quote API (with automatic Yahoo Finance fallback) for offer price, Day-1 close, volume, and benchmark indices.
  3. `hkma`: Retrieves Exchange Fund base rates and HIBOR benchmark rates with local CSV interval caching.
  4. `hsic`: Maps Hang Seng Industry Classification industry codes.
  5. `aftermarket`: Computes 1-month and 6-month Buy-and-Hold Returns (BHR), Wealth Relatives (WR), and liquidity decay ratios.
  6. `academic`: Derives underpricing rate, lottery rationing variables, and cornerstone share proportions.
  7. `audit` & `cross_check`: Executes statutory Listing Rules and econometric consistency audits.

#### Stage 6: Export, Master Panel & Bundle Delivery / 第六步：数据导出、主面板合并与成果打包
- **Commands / 命令**:
  ```bash
  python3 run.py export --config CONFIG
  python3 run.py master --derive
  python3 run.py bundle --run-dir deliverables/run_<board>_<period>
  ```
- **Deliverables / 交付成果**:
  - `HKIPO-MB<period>_clean.csv`: Clean, econometrically typed dataset.
  - `HKIPO_<period>_Codebook.md`: Auto-generated academic variable dictionary with sample distributions.
  - `HKIPO-MB-MASTER_clean.csv`: Updated cross-cohort master panel.
  - `deliverables/HKIPO_<board>_<period>_bundle.zip`: Comprehensive archive containing workbooks, CSVs, codebooks, audit logs, `manifest.json`, and `quality_summary.json`.

## 2. 0-Token Native Geometric Table Parser / 0-Token 原生几何表格解析引擎

### Why Native Geometric Parsing? / 为什么需要原生几何解析？

Hong Kong IPO prospectuses contain hundreds of pages of complex, borderless financial and shareholding tables. Relying on raw LLM prompt scraping or naive regex text extraction leads to:
1. **Severe Token Bloat**: Sending hundreds of pages of raw text to LLMs consumes millions of unnecessary tokens.
2. **Column Misalignment**: In borderless tables, multi-column financial figures collapse onto single lines, causing numbers to shift between periods.
3. **Loss of Multi-Year Context**: Stub periods (e.g. 3-month or 6-month stubs) get conflated with full-year numbers.

The **Native Geometric Table Parser (`src/table_parser.py`)** extracts these tables directly from PDF character bounding boxes using PyMuPDF at **zero LLM token cost**.

```text
PDF Character Stream (x0, y0, x1, y1, char)
                   |
                   v
      [ Y-Axis Line Clustering (y_tol = 3.5pt) ]  --> Groups words into exact rows
                   |
                   v
      [ X-Axis Retinal Projection Alignment ]    --> Establishes column boundaries
                   |
                   v
   Clean Markdown Tables wrapped in <!-- TABLE_START --> ... <!-- TABLE_END -->
```

### Four Core Table Extractors / 四大核心表格抽取器

| Table Extractor / 表格抽取器 | Target Variables / 覆盖字段 | Parsing Strategy & Safeguards / 解析策略与防护机制 |
|---|---|---|
| **Share Capital Table**<br>(股本结构表) | `col_L` (Total shares issued), `col_M` (Public offer shares), `col_N` (Placing shares) | **2-Pass Scan**: Pass 1 matches standard line-end numbers (`Total 1,000,000,000 100%`). Pass 2 activates fallback if nominal values (e.g. `US$0.01`) or multi-line text displace the share counts. |
| **Cornerstone Table**<br>(基石投资者表) | `col_CK` (Cornerstone count), `col_CI` (Cornerstone shares), `col_CJ` (Cornerstone investment HK$) | Scans for cornerstone investor names, committed subscription amounts, share counts, and lock-up periods. Rejects generic fund descriptions. |
| **Underwriting Table**<br>(承销费用与佣金表) | `col_AO` (Underwriting commission %), `col_AP` (Incentive fee %), `col_CX` (Net proceeds) | Scans underwriting and listing expense breakdowns; extracts fixed base commissions and discretionary incentive fees separately. |
| **Consolidated Financial Summary**<br>(合并财务摘要三表) | `col_W` (Assets), `col_Z` (Equity), `col_AC` (Liabilities), `col_AF` (Turnover/Revenue), `col_AI` (PBT), `col_AL` (PAT), `col_AX` (R&D), `col_AY` (Top-5 customers) | **X-Coordinate Period Alignment**: Preserves all historical years and stubs exactly; strips percentage-of-revenue columns; **strictly skips parent-only/company-level balance sheets** (`is_company_level_statement`) to protect Group numbers. |

## 3. 2000–2026 Historical Compatibility Guarantees / 2000–2026 跨周期历史兼容保障

To seamlessly analyze the entire 2000–2026 historical horizon (covering 27 listing cohorts), the pipeline implements five historical compatibility guarantees:

### Compatibility Matrix / 历史兼容规则对照表

```text
+------------------------------------+---------------------------------------+---------------------------------------+
| Historical Dimension / 历史维度    | Pre-2004 / Pre-2018 Historical Era    | Modern Era (2018–2026)                |
+------------------------------------+---------------------------------------+---------------------------------------+
| Track Record Years                 | 1997, 1998, 1999 (regex 199\d|20\d\d) | 2020, 2021, 2022, 2023, 2024, 2025    |
| 2-Digit Century Mapping            | yy >= 70 -> 19yy (e.g. 31/12/99)      | yy < 70 -> 20yy                       |
| Accounting Framework               | HKGAAP, SSAP, Combined Statements     | HKFRS, IFRS, CAS (PRC ASBE)           |
| Revenue Terminology                | Turnover (营业额), Net Sales          | Revenue (收益 / 收入)                 |
| Equity Terminology                 | Net assets (净资产), Capital & Reserves| Total equity (权益总额)               |
| Rule 8.09(2) Minimum Market Cap    | < 2004-03-31: HK$ 100M                | >= 2018-02-15: HK$ 500M               |
|                                    | 2004-03-31 to 2018-02-14: HK$ 200M    | (Chapter 18A: 1.5B; 18C: 4.0B / 8.0B) |
| Price Stabilization Dates          | UK format: "15 July 2004"             | US/UK format: "January 28, 2026"      |
| Benchmark Index Availability       | HSI only (pre-HSTECH, pre-2015/2020)  | HSI (^HSI) and HSTECH (HSTECH.HK)     |
| Market Fetching & K-Line Chunking  | Chunked into 730-day windows (>750d); | Standard single/chunked request;      |
|                                    | fqkline/get fallback for 404 .js files| 12M/36M horizon bounded windows       |
+------------------------------------+---------------------------------------+---------------------------------------+
```

### Deep-Dive into Core Guarantees / 核心机制深度解析

#### 1. 1997–1999 Track Record & 2-Digit Century Parsing (`src/periods.py`, `src/table_parser.py`)
- For IPOs listing between 2000 and 2002, the three-year statutory Track Record Period falls into **1997, 1998, and 1999**.
- All date resolution regexes throughout `periods.py`, `table_parser.py`, and `search.py` use `(?:199\d|20\d\d)` rather than hardcoded `20\d\d`.
- Two-digit year parsing implements the standard pivot:
  ```python
  year = (year + 1900 if year >= 70 else year + 2000) if year < 100 else year
  ```
  This ensures that `"31/12/99"` maps safely to `1999-12-31`.

#### 2. Historical Accounting Standards & Group Reorganizations (`src/pdfprep.py`, `tools/search.py`)
- **Combined Accounts (`COMBINED`)**: Before listing, historical issuers underwent corporate reorganizations. Pre-reorganization periods were reported as **Combined Financial Statements** (合并前结合报表) rather than Consolidated Statements. The parser searches for both `CONSOLIDATED` and `COMBINED` Profit and Loss Accounts and Balance Sheets.
- **UK-Style P&L and Balance Sheet**: Historical HK prospectuses under HKGAAP / SSAP utilized `Turnover` instead of `Revenue`, `Profit and loss account` instead of `Statement of profit or loss`, and `Net assets` instead of `Total equity`. These synonyms are fully indexed in `METRIC_PATTERNS` and `search.py`.

#### 3. Date-Aware Listing Rule 8.09(2) Market Cap Validation (`src/cross_check.py`)
HKEX Main Board Rule 8.09(2) minimum expected market capitalization evolved over time:
```python
if listing_date is not None and listing_date < dt.date(2004, 3, 31):
    min_mcap, label = 100e6, "1 亿港元"
elif listing_date is not None and listing_date < dt.date(2018, 2, 15):
    min_mcap, label = 200e6, "2 亿港元"
else:
    min_mcap, label = 500e6, "5 亿港元"
```
Evaluating a 2001 IPO against the modern HK$500M threshold would produce false validation errors; the date-aware validator enforces the correct statutory requirement applicable on the listing date.

#### 4. Cross-Decade Stabilization Announcement Parsing (`src/stabilization_panel.py`)
Historical price stabilization announcements under Chapter 571W frequently formatted dates using British order (`15 July 2004`), whereas modern announcements often include day-of-week and US order (`Wednesday, January 28, 2026`). The date parser recognizes both patterns seamlessly across `199\d|20\d\d`.

#### 5. Pre-HSTECH Benchmark Fallback & K-Line Chunking (`src/market_fetcher.py`, `tools/external/aftermarket.py`)
- **Pre-HSTECH Graceful Handling**: The Hang Seng TECH Index was launched in July 2020 (backcalculated to 2015). For listings before 2015/2020, `hstech_bars` returns empty without throwing exceptions, allowing HSI market-adjusted returns and wealth relatives to compute without interruption.
- **730-Day K-Line Window Chunking**: The Tencent Quote API truncates single requests to 640 bars. When fetching multi-year post-IPO periods (`> 750` days), `market_fetcher.py` automatically slices requests into 730-day windows and stitches them seamlessly.
- **HTTP 404 Fallback**: Historical Tencent yearly `.js` static files can return 404 for early 2000s stocks; the provider automatically falls back to `fqkline/get` and Yahoo Finance (`^HSI`).
- **Horizon Bounding**: Per-issuer price queries are strictly bounded to the observation window (12 calendar months for `aftermarket.py`, 36 months for `market_panel.py`), avoiding unbound API queries.

## 4. Token & API Cost Optimization Discipline / Token 与 API 成本优化纪律

When collecting large cohorts (e.g. 100+ IPOs), unoptimized LLM calls can exhaust API rate limits and waste substantial budgets. Every agent and operator must follow these mandatory rules:

### 1. Issuer-Level Bundling (`run.py work next`)
- **Rule**: Never spawn separate extractor agents for `prospectus`, `allot`, and `gem` targets of the same issuer.
- **Benefit**: Spawning one extractor per issuer allows the agent to read the shared corporate background, share structure, and cornerstone disclosures **once**, saving up to 60% of context tokens.

### 2. Zero-Token Deterministic Fields
- **Rule**: Do not spend LLM tokens querying fields that the pipeline derives or injects deterministically:
  - `col_CV` (Greenshoe exercise): derived by `derive_allot`.
  - `col_CK` (Cornerstone absence): set to 0 when no cornerstone exists.
  - `col_CQ` (Pricing date): derived from allotment announcement date.
  - `col_DA/DB/DC` (Free float): computed from share structure.
  - `col_CR` (Allotment announcement datetime): pre-injected in the brief.
  - `col_BC` and `col_CN/CO/CP`: computed deterministically by `disclosure_notes`.
  - All market returns, HIBOR rates, HSIC codes, and academic regression variables: computed in Stage 5.

### 3. Excerpt-First Review & Single-Pass Search
- **Extractors**: Read the brief (which embeds `search periods`, `search sharecap`, and `col_CR`) and the deduplicated packet first. If specific values are missing, query all candidates in **one** call:
  ```bash
  python3 run.py search bundle CODE --fields col_W,col_Z,col_AC,col_AF
  ```
- **Reviewers**: Inspect the 700-character excerpts in the Brief's `Review sheet`. Do not open entire 500-page disclosures unless an excerpt is truncated, flagged with a validation warning, or marked missing (`NaN`/`NA`).

### 4. No Redundant Topic Packets (`--no-topics`)
- The pipeline default builds a single, deduplicated markdown packet `HKIPO-MBxxxx.md` rather than slicing redundant topic sub-packets.

### 5. Rate-Limit-Safe Concurrency Caps
- If your LLM provider enforces strict Requests-Per-Minute (RPM) or Tokens-Per-Minute (TPM) limits, cap the active leases using:
  ```bash
  python3 run.py work next --config CONFIG --max-extract 3 --max-review 3 --max-total 4
  ```

## 5. Complete CLI Execution Guide / 命令行全流程执行速查表

### Standard Operating Procedure / 标准操作流程

```bash
# ==============================================================================
# 1. 环境准备与依赖锁定 / Environment Bootstrap
# ==============================================================================
python3 tools/bootstrap.py --profile dev
source .venv/bin/activate

# ==============================================================================
# 2. 跨周期规划与计划预览 / Plan & Scope Preview
# ==============================================================================
python3 run.py plan 2025Q4
# 跨周期多年规划示例 / Multi-year plan example:
# python3 run.py plan 2000..2026

# ==============================================================================
# 3. 启动官方发现与原生预解析 / Start Discovery & Native Pre-Parsing
# ==============================================================================
python3 run.py start --board MB --period-start 2025-10-01 --period-end 2025-12-31
# 命令在完成下载与 0-token 表格预解析后退出，返回 Exit Code 3 (WORK_PENDING)

# ==============================================================================
# 4. 申领租约与执行抽取 / Claim Leases & Extract
# ==============================================================================
# 查看当前待办状态 / Check queue status:
python3 run.py work status --config pipeline/prospectus_pipeline/datasets/HKIPO_2025-10-01_2025-12-31_HKIPO-MB/cohort.yaml

# 申领下一个发行人任务（父智能体调度）/ Claim next bundled lease:
python3 run.py work next --config pipeline/prospectus_pipeline/datasets/HKIPO_2025-10-01_2025-12-31_HKIPO-MB/cohort.yaml

# 子智能体完成抽取后提交 / Complete extraction lease:
python3 run.py work finish-extract --lease <LEASE_ID>

# ==============================================================================
# 5. 独立复核签署 / Independent Review Sign-Off
# ==============================================================================
# 独立复核智能体申领复核任务 / Claim review lease:
python3 run.py work next --config pipeline/prospectus_pipeline/datasets/HKIPO_2025-10-01_2025-12-31_HKIPO-MB/cohort.yaml

python3 run.py work finish-review --lease <LEASE_ID> --verdict pass --reviewer "ReviewerAgent"

# ==============================================================================
# 6. 哈希门禁回写与外部计量增广 / Hash-Gated Resume & Enrichment

# ==============================================================================
# 7. 导出、跨年主面板合并与归档 / Export, Master & Bundle

# 合并至跨年 master 面板:
python3 run.py master --derive

# 打包发布 ZIP 交付成果物:
python3 run.py bundle --run-dir deliverables/run_MB_2025-10-01_2025-12-31
```
